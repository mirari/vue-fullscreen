# 选择全屏方式

先选择控制入口，再选择显示方式。两者相互独立：组件、指令和 API 都支持 `pageOnly` 与 `teleport`。

## 三种控制入口

| 入口 | 控制方式                                   | 典型用途                       |
| ---- | ------------------------------------------ | ------------------------------ |
| 组件 | `v-model` 双向同步状态                     | 图表面板、图片容器、播放器外壳 |
| 指令 | 点击绑定的元素触发切换                     | 给工具栏按钮快速增加全屏能力   |
| API  | `request` / `toggle` / `exit` 返回 Promise | 接入现有业务逻辑、控制指定 DOM |

组件各自持有控制器，指令共用公开的 `api` 单例。避免同时对多个目标发起竞争性的原生全屏请求。

## 两种全屏模式

|              | 原生全屏                       | 网页全屏                |
| ------------ | ------------------------------ | ----------------------- |
| 配置         | `pageOnly: false`（默认）      | `pageOnly: true`        |
| 显示范围     | 浏览器提供的全屏区域           | 当前网页视口            |
| 浏览器工具栏 | 由浏览器隐藏                   | 保留                    |
| 用户手势     | 需要点击、按键等用户操作       | 不需要                  |
| 退出         | 浏览器 Esc、退出按钮、`exit()` | Esc、退出按钮、`exit()` |

如果浏览器不支持原生全屏，库自动使用网页全屏。如果浏览器支持但拒绝请求，库会报告错误并恢复 DOM，而不是静默切换模式。

## teleport 解决什么问题？

开启 `teleport` 后，全屏目标临时移到 `document.body`，退出时恢复原位置。原生模式此时请求 body 全屏，让同样挂载到 body 的弹窗有机会显示。

- `teleport: false`：目标保留在原父节点，适合布局简单的区域。
- `teleport: true`：适合带弹窗、下拉层或被父容器裁剪的内容。
- 目标本来就是 body 时，不会再移动。

移动后，依赖祖先选择器的 CSS（例如 `.dashboard .panel`）可能不再匹配。把全屏背景、滚动和层级直接设置在目标类名上。库不强制设置背景色、`z-index` 或滚动策略。

```css
.my-fullscreen {
  background: white;
  overflow: auto;
  z-index: 1000;
}
```
