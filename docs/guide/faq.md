# 常见问题

## 为什么页面加载后不能自动进入原生全屏？

原生全屏**只能由**点击、触摸或按键等用户操作触发，这是浏览器的用户激活限制。请在事件处理函数中直接发起请求；等待网络响应或计时器后再调用，可能因用户激活状态过期而被拒绝。如果需要无需用户操作就自动放大内容，可使用 `pageOnly: true`。详见[用户操作与 iframe 权限](/guide/compatibility#用户操作与-iframe-权限)。

## 点击后没有进入原生全屏？

先检查错误事件或 Promise 拒绝。嵌入 iframe 时还需要宿主允许 fullscreen 权限。

`isEnabled` 只表示 API 可用，不保证每次请求都被批准。可先启用 `pageOnly`，排除原生权限问题。

## 手机上的表现为什么不同？

不同浏览器、设备及嵌入方式的原生全屏支持不同。不支持时库会降级到网页全屏；网页全屏仍保留浏览器工具栏。请在目标设备上验证，而不是根据桌面浏览器推断。

## 弹窗或下拉菜单看不到？

浏览器只显示原生全屏元素及其后代，提高 `z-index` 无法显示其外部的弹窗。开启 `teleport` 并配置 UI 库将弹窗挂载到 `body`，或关闭 `teleport`、将弹窗直接挂载在全屏目标内部。可在[快速上手](/guide/getting-started)对比效果。

## teleport 后样式变了？

元素从原父节点移动到了 body。依赖祖先的 CSS 选择器和继承值可能失效；把关键样式放到目标自身的 class 上。退出时会恢复原 DOM 位置和被库修改的行内布局样式。

通过 `fullscreenClass` 设置背景、滚动和层级；库不会强制设置这些样式：

```css
.my-fullscreen {
  background: white;
  overflow: auto;
  z-index: 1000;
}
```

## SSR 或 Nuxt 可以用吗？

可以在服务端导入包。只在浏览器挂载后读取 DOM，并在用户操作中请求原生全屏。不要在服务端调用 `enter()`。
